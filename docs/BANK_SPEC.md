# مشخصات اپ نمونه «فم بانک» — منبع ایده پورت به Mostafa App

این سند مشخصات کامل اپ مستقل نمونه‌ای است که کاربر به‌صورت فایل zip داد
(`bank-haghighi-credit-equals-total-share-deposits.zip`). آن اپ یک HTML/PWA مستقل
با نسخه اندروید است و داده‌هایش در `localStorage` با کلید `family_fund_data_v2`
نگه‌داری می‌شود. هدف: بازتولید همین قابلیت‌ها به‌صورت بخش «فم بانک» داخل
Mostafa App (Next.js + JSON)، با همان منطق و فرمول‌ها.

نقشه اجرای این پورت در `docs/STEPS.md` است؛ هر استپ از این سند ارجاع می‌گیرد.

## ۱) امکانات اپ نمونه (لیست کامل)

1. مدیریت اعضا (سهامدارها)، واریزی‌ها، وام‌ها، اقساط و تسویه نهایی اعضا.
2. نمایش طلب، بدهی و مانده خالص هر عضو در «پرونده مالی» عضو.
3. **اعتبار عضو = جمع واریزی‌های سهام عضو** (این همان فیچر اصلی نام فایل نمونه است؛
   برچسب در UI: «اعتبار (جمع واریزی سهام)»).
4. ثبت سود وام و عنوان‌های آماده واریزی قابل مدیریت.
5. تقویم شمسی با امکان انتخاب تاریخ گذشته و ساعت خودکار قابل ویرایش.
6. ثبت سریع واریزی و پرداخت سریع سهم ماهانه.
7. قفل محلی مدیر (PIN با هش SHA-256) و شخصی‌سازی ظاهر.
8. جست‌وجوی اعضا، واریزی‌ها و وام‌ها (با نرمال‌سازی اعداد فارسی/عربی).
9. هشدار تراکنش مشابه پیش از ثبت.
10. ثبت سوابق ثبت/ویرایش/حذف/لغو تسویه/بازیابی پشتیبان (audit، حداکثر ۱۰۰۰ رکورد).
11. گزارش عضو، گردش ماهانه و خلاصه سالانه.
12. خروجی CSV سازگار با Excel (UTF-8) و چاپ گزارش / ذخیره PDF از پنجره چاپ مرورگر.
13. پشتیبان‌گیری JSON با نام تاریخ‌دار و اعتبارسنجی فایل هنگام بازیابی.
14. محاسبه موجودی صندوق از کل تراکنش‌ها.

## ۲) مدل داده اپ نمونه (فیلدهای دقیق)

### member (عضو / سهامدار)

| --- | --- |
| `id` | شناسه یکتا |
| `name` | نام (الزامی) |
| `shares` | تعداد سهم (عدد > 0) |
| `phone` | تلفن |

| `totalDeposited` | جمع واریزی‌ها — با هر ذخیره در `recalc` بازمحاسبه می‌شود |
| `settled` | وضعیت تسویه نهایی (boolean) |

| `settledAt` | زمان تسویه |
| `note` | یادداشت |
| `createdAt` | ISO — مبنای شروع تعهد ماهانه |

### deposit (واریزی)
| فیلد | توضیح |
| --- | --- |
| `id` | شناسه |
| `memberId` | شناسه عضو؛ `null` یعنی «واریزی متفرقه» (بدون عضو) |
| `memberName` | نام عضو در لحظه ثبت (برای نمایش) |
| `type` | `share` (سهم ماهانه) / `loan_interest` (سود وام) / `profit` (واریزی سود) / `misc` (متفرقه) |
| `title` | عنوان واریزی (از فهرست عنوان‌های آماده یا آزاد) |
| `amount` | مبلغ (تومان) |
| `periodKey` / `month` | دوره ماه شمسی به شکل `yyyy/mm` — فقط برای `type=share` معنادار |
| `createdAt` | ISO — تاریخ/ساعت واقعی ثبت |

### loan (وام)
| فیلد | توضیح |
| --- | --- |
| `id`, `memberId`, `memberName` | شناسه‌ها |
| `principal` | اصل وام |
| `interest` / `interestMode` | مبلغ سود و حالت کسر: `beginning` (از اصل کسر می‌شود) یا `end` (به اصل اضافه می‌شود) |
| `interestAmount` | مبلغ سود |
| `totalAmount` | کل بدهی وام (اصل ± سود) |

### fund / settings (تنظیمات صندوق)
| فیلد | توضیح |
| --- | --- |

## ۳) فرمول‌های دقیق (باید عیناً در Mostafa App پیاده شود)

- **اعتبار عضو (credit)** = مجموع همه واریزی‌های `type=share` آن عضو. (تابع
  `memberClaim` در نمونه — همان فیچر نام فایل zip.)
- **تعهد ماهانه هر عضو** = `تعداد سهم × amountPerShare`.
- **محاسبه تعهد/مانده سهام** (`memberShareDue` در نمونه):
  - ماه جاری و ماه‌ها با تقویم شمسی (`yyyy/mm`) و سری ماه = `سال×۱۲ + ماه − ۱`.
  - `priorDue = max(0, فاصله ماهی از ماه عضویت تا ماه قبل) × تعهد ماهانه`
  - `priorPaid` = جمع واریزی سهام ماه‌های قبل؛ `currentPaid` = جمع واریزی سهام ماه جاری.
  - `priorCarry = max(0, priorPaid − priorDue)` (اعتبار قابل استفاده ابتدای ماه).
  - `available = priorCarry + currentPaid`؛ `left = max(0, تعهد ماهانه − available)`؛
    `paid = min(تعهد ماهانه, available)`؛ `overdue = left > 0`.
  - **موجودی/اعتبار نهایی عضو** = کل واریزی سهام تا این ماه − کل تعهد سهام تا این ماه.
- **بدهی عضو** (`memberDebt`) = Σ مانده وام‌های عضو + مانده تعهد سهام (`left`).
- **طلب عضو** = اعتبار (جمع واریزی سهام). **مانده خالص** = طلب − بدهی.
- **پرداخت‌شده وام** (`loanPaid`) = Σ `payments.amount`.
- **مانده وام** (`loanRemaining`) = `max(0, totalAmount − پرداخت‌شده)`.
- **جدول اقساط** (`makeSchedule`):
  - حالت خودکار: مبالغ مساوی `floor(total/months)`؛ قسط آخر مابقی را می‌گیرد.
  - حالت دستی: مبالغ جدا با کاما یا خط جدید؛ تعداد باید برابر months و جمعشان دقیقاً
    برابر total باشد؛ در غیر این صورت خطا.
  - تاریخ قسط‌ها ماه‌به‌ماه از «تاریخ اولین قسط شمسی» جلو می‌رود (ساعت ۱۲:۰۰).
- **موجودی صندوق** (`recalc`): `Σ همه واریزی‌ها + Σ بازپرداخت‌ها − Σ disbursedAmount وام‌ها`.
- **سود کل ثبت‌شده** = Σ واریزی‌های `type=loan_interest` + سود وام‌هایی که مانده‌شان صفر شده.
- **گردش ماهانه** (`monthlyTotals`): گروه‌بندی تراکنش‌ها بر کلید ماه شمسی با ستون‌های
  `share` (سهم)، `interest` (سود وام)، `profit` (سود واریزی)، `repayment` (بازپرداخت)،
  `loanOut` (پرداخت وام) — مرتب از ماه جدید به قدیم.

## ۴) رفتارهای مهم UI نمونه

- کارت عضو با رنگ‌بندی وضعیت: قرمز اگر تعهد پرداخت‌نشده عقب‌افتاده دارد؛
  تسویه‌شده با خط‌خوردگی نام (سبز اگر بستانکار، متمایز اگر بدهکار).
- جست‌وجو با نرمال‌سازی: حروف فارسی/عربی یکسان‌سازی و تبدیل اعداد فارسی/عربی به لاتین.
- «هشدار تراکنش مشابه» پیش از ثبت: همان عضو + مبلغ + ماه یکسان → تأیید گرفته می‌شود.
- «پرداخت سریع سهم ماهانه»: از کارت عضو، مبلغ تعهد ماهانه جاری را یک‌جا ثبت می‌کند.
- تقویم شمسی سفارشی: انتخاب روز (تاریخ گذشته هم مجاز)، ساعت پیش‌فرض = زمان فعلی و قابل ویرایش.
- پارس دوره ماه (`parseSharePeriod`): ورودی آزاد را می‌فهمد — `۱۴۰۵/۰۸`، `1405-8`،
  «آبان ۱۴۰۵»، «آبان ۰۵» و اعداد فارسی/عربی؛ خروجی استاندارد `yyyy/mm` شمسی.
- تسویه نهایی: پیش‌فرض طلب/بدهی از محاسبات، ولی قابل ویرایش دستی؛ مانده خالص زنده
  به‌روز می‌شود؛ امکان «لغو وضعیت تسویه».
- پشتیبان JSON با نام شامل تاریخ، و بازیابی با اعتبارسنجی ساختار.
- تاریخ‌ها برای نمایش با `Intl.DateTimeFormat('fa-IR-u-ca-persian')` شمسی می‌شوند.

## ۵) محدودیت‌های نمونه و تفاوت‌ها با Mostafa App

- نمونه داده را در `localStorage` مرورگر نگه می‌دارد؛ Mostafa App داده را در
  `data/db.json` سمت سرور (با `lib/db.ts`) نگه می‌دارد — همین جایگزین localStorage است.
- قفل مدیر در نمونه صرفاً محلی است و امنیت سروری نیست؛ در پورت هم فقط قفل ظاهری UI است.
- در Vercel نوشتن داده به `/tmp` می‌رود و ماندگاری محدود دارد (رفتار فعلی کل پروژه،
  از قبل موجود)؛ پشتیبان‌گیری/بازیابی JSON راه استفاده عملی است. سرویس خارجی جدید
  بدون اجازه کاربر اضافه نمی‌شود.
